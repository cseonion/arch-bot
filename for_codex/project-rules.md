# 프로젝트 작업 원칙

## 제품 방향

- 비개발자가 Discord에서 건축 관련 AI 에이전트를 자연스럽게 사용할 수 있게
  한다.
- 채널은 서로 다른 업무, 시스템 프롬프트, Tool, MCP, Skill과 대화 상태를 가진
  에이전트 경계다.
- 기능은 작은 단위로 구현하고 테스트한 뒤 Git 커밋과 Draft PR에 정리한다.

## 언어와 진실성

- 사용자 문서, 변경 기록, PR과 Release 설명은 한국어로 작성한다.
- 코드 식별자와 공식 제품명은 필요한 경우 영어를 유지한다.
- 파일을 접수한 것, 메타데이터만 추출한 것, 실제 내용을 분석한 것을 구분한다.
- 구현되지 않았거나 검증하지 않은 기능을 작동한다고 설명하지 않는다.

## 완료 기준

- 요청된 코드와 설정이 저장소 구조에 반영되어 있다.
- 정상 흐름과 중요한 실패 흐름에 테스트가 있다.
- `ruff check .`, `pytest`, `git diff --check`가 통과한다.
- 사용자 영향은 `README.md`, 개발 영향은 `README_dev.md`에 반영한다.
- `CHANGELOG.md`의 `[미출시]` 두 단을 갱신한다.
- 지속 규칙이 바뀌었다면 `for_codex` 정본도 갱신한다.
